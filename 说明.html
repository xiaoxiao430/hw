01 · 从哪里开始

让学生看懂自己的变化，让教师把发现接到支持与复看，让家庭获得清楚可行的配合方式，让集团了解支持落实与教学改进的条件。

  1. macOS 双击交付根目录的“本地启动.command”。也可用 Python 3 执行同目录“启动.py”；均仅使用标准库，无需安装 npm 或 Python 包。
  2. 启动器自动选择空闲本地端口并打开浏览器，仅绑定 127.0.0.1。关闭终端或按 Control + C 停止服务。
  3. 顶部切换角色和初高中；手机点击右上角切换入口。先用教师端体验主流程，再切家长或学生查看变化。
  4. 点击“重置演示”恢复合成样本。操作保存在当前浏览器的当前站点；同一站点的标签页可同步。更换浏览器、设备或端口会使用独立状态。

本地包资源完整，断网也可以运行。Python 3 是本地启动所需运行环境；不需依赖远程字体、CDN 或第三方脚本服务。

03 · 五组场景怎样操作

一、作业与考试 → 支持 → 再次反馈 → 家庭近况

  1. 教师工作台点击“查看并安排支持”，展开原题、来源、学生作答与知识点；点击“安排学习支持”，填写行动、跟进人和复看日期。
  2. 进入这条支持，分别体验“已有改善”与“仍需支持”，补充具体观察。有改善后可以完成本项支持。
  3. 整理本周反馈，修改“近期变化／学校已做什么／家庭可以怎样配合／学生的下一步”，保存并确认，再发布。
  4. 切到家长端“近况”和学生端“本周”，查看同一份已发布反馈。发布前，家庭不会收到教师草稿。

二、课堂讨论 → 课后跟进

  1. 从教师工具进入课堂，录入独立作答的 36 人合成分布，再进入同伴讨论。
  2. 录入再次作答，比较前后分布，收集出口反馈。纸笔或公共设备参与由模拟录入代表。
  3. 生成课后跟进或提交课堂成长；回教师端继续处理。重复操作不会重复创建同一条课堂事项。

三、学生表达 → 教师复核 → 全面成长

  1. 学生保存一段私人复盘，再切教师确认草稿不可见；学生选择提交给数学老师，并选择是否申请家庭分享。
  2. 教师阅读并确认复盘，系统生成待复核成长记录。教师再确认成长记录后，已选择分享的内容才进入家长成长页。
  3. 学生也可记录作品、运动、劳动或实践，写出实际贡献、收到的反馈与反思。未选择家庭分享的内容保留在师生范围。

四、专业研判 → 必要支持协作

  1. 专业老师进入合成案例，查看详细反馈，点击“研判后创建安全协作事项”。
  2. 切班主任查看必要行动、负责人和复看要求。普通家庭页与课堂大屏不接收原始心理记录。
  3. 更新协作观察或完成支持；集团只查看支持落实数量，不下钻专业私密内容。

五、集团观察 → 教研复看与资源协作

  1. 集团端按初高中及香江路／兴国路校区筛选，查看相应范围的学习、成长和支持汇总。
  2. 打开教研案例，结合覆盖样本、教学条件、前后表现与教师用时理解变化，安排下一次复看和资源协作。
  3. 切换高中版，体验“导数题先判断参数条件，再比较解题路径”的完整差异案例。初中重点为一次函数情境、订正与解释习惯。

教研中的前后变化是合成观察资料，不能直接解释为某个教学方法带来的因果效果。管理页面的学生汇总与课堂 36 人答题分布属于不同模拟样本。

04 · 原始记录、建议与发布状态

对象状态与门槛家庭何时可见
作业、考试原始记录保留来源编号、来源、题目、学生、知识点和日期。新导入记录标记“原始数据 · 待教师解读”相关教师反馈确认并发布后，关联学情才发布；新导入不直接对家庭开放
系统建议与反馈模拟草稿 → 教师修改 → confirmed 确认 → published 发布；已确认后再修改，回到草稿仅 published 可见；不能跳过教师确认直接发布
学生复盘draft 草稿 → submitted 提交给明确教师 → confirmed 教师阅读确认；私人草稿不进入教师投影家长不直接读取复盘列表；学生选分享后，经成长复核进入已发布成长记录
成长记录pending 待复核 → confirmed 教师确认；另保存 published 家庭发布标记同时满足教师确认与家庭发布。学生自主记录保留分享选择
支持事项planned 已安排 → improving 有改善／continued 继续支持 → closed 完成学科学习行动在本人支持视图可见；专业协作详情留在受限教师范围，通过教师沟通形成适当家庭反馈

05 · 可调用的数据适配入口

Store.importRecords(rows, ctx, options) 接受作业／考试数组，返回 {ok, message, added, duplicates, errors}。Store.adapters.normalizeRecords 只规范化与校验，不写入。此入口处理合成对象，不发送网络请求。

const rows = [{
  sourceId: 'XF-DEMO-001',
  source: '讯飞作业（模拟）',
  externalStudentId: 'EXT-001',
  type: 'homework', subject: '数学',
  date: '2026-10-30', title: '情境中的起始量',
  knowledge: '一次函数图像与情境',
  question: '水箱原有20升水，每分钟注水3升，如何表达数量关系？',
  answer: 'y=3x+20，20为起始量。',
  studentAnswer: 'y=3x+20。',
  errorReason: '需要进一步听取学生对起始量的解释。',
  score: 8, maxScore: 10
}];
Store.importRecords(
  rows,
  {role:'teacher', stage:'junior', teacherKind:'head'},
  {studentMap:{'EXT-001':'j1'}}
);
来源字段本地字段与约束
外部学生编号externalStudentId 经 options.studentMap 映射到 studentId；也可传已知 studentId。必须属于当前教师的学段与班级范围
源系统、记录编号source、sourceId 必填；与 type、studentId 组成去重键。相同记录重复导入跳过
类型、学科、时间type 为 homework 或 exam；subject 必填；date 为有效 YYYY-MM-DD 日期
题目与表现title、knowledge、question 必填；answer、studentAnswer、errorReason 可补充，保留原始依据
分数与满分score、maxScore 为有效数字；满分大于 0，分数介于 0 和满分之间。比较时保持学科和满分口径一致
确认发布标记输入 id、status、published 不被采信；本地生成记录 ID，统一进入待教师解读状态

每批 1—500 条；任一无效行整批拒绝，不部分写入。初中样本 j1／j2 在香江路，高中 s1／s2 在兴国路；外部身份映射需要正式系统验证，不能沿用演示编号。页面数据来源可模拟“缺失”“失败”，恢复后安全重试；原有记录保留。

06 · Demo 与正式接入的区别

本轮完成可点击网页、角色投影和共享本地流程。没有调用讯飞、考试、成长档案或心理系统，没有使用真实 AI 模型，没有改动数据库、微信小程序发布包或生产后台。

  • 当前 Store 是浏览器模拟数据层，Store.get() 仅用于内部 QA；浏览器中存在完整合成样本。前端隐藏字段不能替代服务端鉴权。
  • 正式接入需核验学校、班级、科任与家长绑定关系；由服务端返回授权数据，隔离专业原始记录，并审计确认、发布和撤回。
  • 来源编号、字段、学生主数据、数据可用性和同步机制仍需各系统联调；本轮仅保留适配入口及发布门槛。
  • 草稿中的解读和建议均为预置模拟文本。正式 AI 结果仍需教师核实，学生状态不能由单次分数或量表自动定性。
  • 同一浏览器同站点的标签页同步，不代表不同人员、设备或服务器之间的实时协作。
